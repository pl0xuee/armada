# Releasing Armada

Installed copies of Armada check GitHub Releases for updates (15 seconds after launch, then every 6 hours, plus Settings → About → "Check for updates").

- **Windows, macOS, Linux AppImage** install updates in place. The updater reads `latest.json` from the latest published release and verifies each download against the public key in `apps/desktop/src-tauri/tauri.conf.json` before installing.
- **deb / rpm** installs are owned by the system package manager. Armada asks the GitHub Releases API whether a newer version exists and links to the release page.

## Release notes

Every release has notes, written in [`CHANGELOG.md`](../CHANGELOG.md). Add user-facing entries under `## Unreleased` as you go (what changed for people using the app, not commit subjects). The section for a version becomes:

- the GitHub release body (followed by install instructions and a "Full changelog" compare link), and
- the notes shown by the in-app updater ("Release notes" on the update pill), via `latest.json`.

`scripts/release_notes.py` enforces this. CI runs `release_notes.py --check`, which fails when the version in `Cargo.toml` has no non-empty section. The Release workflow fails before building anything when the tag has none. Preview a release body with `python3 scripts/release_notes.py v0.2.0`.

## Cutting a release

1. Bump the version everywhere (they must match the tag; the Release workflow refuses to build otherwise):
   - `Cargo.toml` → `[workspace.package] version` (then `cargo check` to update `Cargo.lock`)
   - `apps/desktop/package.json` and `apps/remote/package.json` → `version` (then `npm install` in each to update the lock files)
   - `tauri.conf.json` has no version on purpose: Tauri takes it from `Cargo.toml`.
2. In `CHANGELOG.md`, rename `## Unreleased` to `## v0.2.0 — <date>`, review the notes, and start a fresh empty `## Unreleased` above it.
3. Commit, then tag and push:
   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```
4. The **Release** workflow first checks that the tag matches the version, that `CHANGELOG.md` has notes for it, and that CI passed on the tagged commit (it does not re-run tests). CI only runs the release-profile build and the deb bundle + e2e smoke (which launches the real debug app under Xvfb and drives it with WebDriver, `apps/desktop/e2e`) on pushes to `main`, so tag a commit that has been merged to `main` and wait for its CI run to finish. It then builds macOS (universal), Windows and Linux installers, signs the update bundles and uploads everything plus `latest.json` to a **draft** release with the notes as its body.
5. Review the draft on GitHub and press **Publish**. Edits to the draft's notes change the GitHub page only: the in-app updater reads the copy already baked into `latest.json`, so fix notes in `CHANGELOG.md` before tagging. Only published releases are visible to the updater, so this is the moment the update rolls out.

## Signing key

The gate requires these jobs: `checks (linux)`, `macOS`, `Windows`, `release build (linux)` and `deb bundle + e2e smoke (linux)`. Renaming a job in `ci.yml` means updating the `required=(...)` list in `release.yml`'s verify job (and any branch-protection required checks) too. Docs-only PRs skip `checks` and `native` through the `changes` job; skipped counts as passing.

Run the e2e smoke locally with `apps/desktop/e2e/run.sh` after `npm run tauri build -- --debug --no-bundle` (needs `tauri-driver`, `WebKitWebDriver`, `xvfb`).

Update bundles are signed with a minisign key generated by `tauri signer generate`.

| What | Where |
|---|---|
| Public key | `plugins.updater.pubkey` in `tauri.conf.json` (committed) |
| Private key | `~/.tauri/armada-updater.key` on the maintainer's machine, and the `TAURI_SIGNING_PRIVATE_KEY` repo secret |
| Key password | `~/.tauri/armada-updater.password`, and the `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` repo secret |

**Back up the private key and password.** If they're lost, existing installs can't verify future updates. Every user would have to reinstall manually once a new key ships.

To set or rotate the secrets:

```bash
gh secret set TAURI_SIGNING_PRIVATE_KEY < ~/.tauri/armada-updater.key
gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD < ~/.tauri/armada-updater.password
```

## Optional: OS code signing

`release.yml` has commented placeholders for Apple notarization and Windows Authenticode. Without them, macOS Gatekeeper and Windows SmartScreen show a warning on first install. Updates still verify through the updater key above.

## Building locally

The phone companion is embedded into the desktop binary, and release builds refuse to compile without it:

```bash
(cd apps/remote && npm ci && npm run build)
cd apps/desktop && npm ci && npm run tauri build
```

(`beforeBuildCommand` rebuilds it too; set `ARMADA_ALLOW_MISSING_REMOTE=1` only for throwaway builds.)
